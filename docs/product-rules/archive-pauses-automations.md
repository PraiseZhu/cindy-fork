# 归档绑定了自动化的任务前先确认

## 适用场景

任务被一个或多个**运行中**（`active`）的自动化绑定（`targetSessionId` 指向该任务），用户手动归档这个任务。

## 现有行为（不在本规则内改变）

自动化下次触发时，调度器发现绑定的任务已归档，就暂停这条自动化（本轮记为跳过）；
**持续会话**（`persistentSession`）例外，它会换绑一个新任务继续运行。归档那一刻本身不改动自动化，
取消归档也不会恢复已暂停的自动化。

## 产品不变量

1. **归档前先确认**：任务绑定了归档后会停掉的自动化（运行中、非持续会话）时，用户入口先弹确认，
   写明哪些自动化会暂停（单个任务列出名称，批量归档给出受影响的任务数）。
2. 没有这类绑定的普通任务维持「归档不弹确认」的原有体验，不增加等待。
3. 已暂停、已过期、持续会话的自动化不提示；伙伴例行任务按伙伴生命周期管理，不在此列。

## 原因

此前归档后，绑定的自动化会在下一次触发时被静默停掉，用户事先不知道，事后才发现自动化不再运行。

## 验收

- 桌面：侧栏单条 / 行内归档、批量归档、项目「全部归档」、标题栏菜单、硬件快捷键、文件浏览
  模式关闭任务，遇到上述绑定时均出现带自动化提示的确认。
- 手机：滑动归档、选项菜单归档、任务详情菜单归档弹系统确认；设备页批量归档的确认条显示
  受影响的任务数。

## 允许的例外

- 绑定信息读取失败（如远程电脑暂时不可达）时，入口按「无绑定」直接归档，不阻塞归档。
- 桌面本机优先使用已有的自动化缓存；冷启动缓存未就绪时最多等待约 1.5 秒，超时按「无绑定」处理，普通任务的归档不会卡在自动化列表请求上。
- 已知边界（不为此新增机制）：桌面本机在自动化刚被创建 / 恢复 / 改绑的同一瞬间，若恰好有一次更早发出的缓存读取还在途，归档提醒可能读到变更前的列表而漏掉新绑定。后果只是回到本规则之前的既有行为（下次触发时由调度器暂停），不丢数据；不为此给共享缓存增加排队重读机制。
- Agent 工具（`archive_sessions`）与 IM 渠道的归档没有确认界面，不在本规则范围内。
